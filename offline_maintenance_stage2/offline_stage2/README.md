# 第二阶段：可复核签名与网关进程故障实验

这一阶段完成两件事：补齐第一阶段遗漏的公钥导出，以便离线复验授权端、网关、维修终端三层签名；把网关重启实验升级为控制端强制终止真实子进程，再启动新进程读取同一数据库与重新加载测试密钥。

当前仍使用机器人和登记服务模拟器，没有接入 EVM 合约、实体机器人、真实可信时钟或电源故障。参考程序可以在 Windows / VS Code 中执行；提供者的附带验证结果是在 Linux 环境运行产生，Windows 结果以你本机运行和上传证据为准。

## 按顺序运行

1. 将本 ZIP 解压到新目录。在 VS Code 打开其中 offline_stage2 文件夹，不覆盖你已经跑过的旧 results。
2. 打开终端，执行以下命令。Python 3.9.13 可以继续使用；依赖与第一阶段相同。

```bash
python -m pip install -r requirements.txt
python run_experiments.py --output results_with_keys
python verify_evidence.py --input results_with_keys
python run_process_experiments.py --repeats 3 --output stage2_results
python verify_evidence.py --input stage2_results
```

依次预期看到：

- 第一阶段增强导出：26/26 passed。
- 第一阶段离线验签：audit_success 为 true，local_records_verified 为 18；修改日志的那次提交应确认为无效签名。
- 第二阶段：21/21 passed，forced terminations 为 18。
- 第二阶段离线验签：audit_success 为 true，local_records_verified 为 24。

每一种进程实验默认重复 3 次。P5 是响应丢失与新进程重试，没有强制终止；其余 6 种每次各强制终止 1 次，所以总计 18 次。3 次重复是这一轮故障复现设置，不是可靠性置信保证。

第二阶段不覆盖已有非空输出目录。需要重跑时改名：

```bash
python run_process_experiments.py --repeats 3 --output stage2_results_rerun
python verify_evidence.py --input stage2_results_rerun
```

第一阶段的导出器仍会覆盖指定目录中的同名结果文件，所以每次独立实验也应使用新目录。运行中若报错，保留该轮结果和完整终端报错，不修改预期值或只保留成功轮次。

## 7 种进程实验

| 编号 | 强制终止位置或故障 | 重启后操作 | 通过标准 |
|---|---|---|---|
| P1 | 次数已预留，机器人尚未调用 | 原请求重试、查询回执、尝试上传和新操作 | 保持 PENDING；不能声称完成；配额不恢复；机器人执行数 0 |
| P2 | 机器人回执已保存，完成日志尚未写入 | 查询独立机器人服务、恢复日志、重试原请求、上传 | RECOVERED、REPLAY、登记一次；机器人实际模拟执行数 1 |
| P3 | 完成日志已持久化，尚未返回结果 | 原请求重试，再提交不同请求 | 原请求 REPLAY；次数用尽时新请求拒绝；不重复执行 |
| P4 | 登记端已接受且回包，但本地尚未标记同步成功 | 新进程重新上传 | 重试 DUPLICATE；登记数仍为 1；本地最终标记已同步 |
| P5 | 登记端已接受，响应连接被关闭 | 另一个新网关进程重试 | 首次 UNAVAILABLE，重试 DUPLICATE；登记数 1 |
| P6 | 完成日志后终止，重启时把时间连续性设为不可信 | 提交另一项新操作 | CLOCK_UNTRUSTED；执行数及已用次数均保持 1 |
| P7 | 两条待传日志，第一条远端接受后、本地标记前终止 | 新进程上传剩余队列 | 先 DUPLICATE，再 ACCEPTED；两条均标记已同步，登记总数 2 |

这些预期值直接固定在 run_process_experiments.py 的 CASES 中。控制器从子进程收到故障点标记后调用进程强制终止，再等待其退出；POSIX 使用 SIGKILL，Windows 使用 TerminateProcess。控制器记录 PID、故障点和非正常退出码。只有网关子进程被终止；独立 HTTP 机器人模拟服务、HTTP 登记模拟服务和控制器继续运行。

## 与第一阶段相比，实质增加的证据

- 新网关实例属于另一个操作系统进程，不再仅关闭并重建 Python 对象。
- 网关私钥从临时测试密钥文件重新加载，SQLite 状态从同一路径重新读取。
- 机器人模拟回执保存在另一个数据库，服务不随网关终止，所以 P2 能独立查询“执行过没有”。
- evidence.json 包含进程事件、机器人调用/查询事件、登记事件、本地快照、登记记录和每个用例对应的三类公钥。
- verify_evidence.py 不导入网关的验签函数；直接用密码库复验导出的签名，核对哈希链接、范围绑定、声明执行时间、配额序号及 CSV/JSON 一致性。

验签脚本信任导出的测试公钥映射。签名一致性不等于外部身份认证，也不能证明真实执行时间、真实维修质量、未知尾部是否完整或隐藏的双签不存在。拒绝请求的全部输入并未逐一导出；验签通过只覆盖输出中的签名记录与已保存的提交证据，不能扩展为所有运行细节均由第三方独立证明。

## 输出与上传

| 文件/目录 | 内容 |
|---|---|
| results.json / results.csv | 预期、实际、通过标记、用例编号及重复编号 |
| evidence.json | 公钥、签名日志、进程终止记录、机器人事件、登记事件和快照 |
| scope.json | 操作系统、Python、依赖版本、重复数、强制终止数和实验边界 |
| audit.json | 独立验签与一致性核查结果 |
| cases/ | 第二阶段每轮的 gateway.sqlite 与 robot.sqlite，用于后续复核 |

完成后把你新生成的 results_with_keys 和 stage2_results 放入同一个文件夹，压缩成 stage2_results_upload.zip 并上传。不要上传附带的 verified_functional 或 verified_stage2；它们是提供者运行结果。

程序会临时生成模拟网关私钥文件，正常结束后删除；结果目录只保留公钥与业务数据库。测试私钥不用于任何真实钱包、机器人或账户。若控制器本身被异常终止，临时文件可能残留；这一实现不验证生产密钥托管或 Windows ACL 安全。

## 已完成的提供者验证

- 增强导出的六组功能用例：26/26 通过；18 条本地记录三层签名与哈希链接复核通过。
- 7 种进程场景各重复 3 次：21/21 通过，实际强制终止 18 次；24 条本地记录复核通过。
- 验签器负对照：修改网关日志、修改授权内容、缺失网关公钥、旧版未导出公钥的结果，均未被判为审计通过。

本包保存真实运行产生的参考结果，不包含假设的性能数据。Python/平台版本以每轮 scope.json 为准。SHA256.json 用来核对文件内容，属于未签名的摘要清单，不能单独作为防篡改信任锚。
