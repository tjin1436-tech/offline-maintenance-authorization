# 机器人断网运维：六组功能与故障实验

这是可以直接运行的软件参考实验包，用来验证“提前签发短期离线授权、网关本地执行、恢复连接后登记”的规则。当前没有接入你原论文的合约，也没有实体机器人。HTTP 登记服务是模拟器，不能把结果写成区块链性能、Gas、共识可靠性或实体维修成功率。

## 1. 先运行全部用例

需要 Python 3.10 或更新版本。进入解压后的目录，安装依赖后执行：

```bash
python -m pip install -r requirements.txt
python run_experiments.py
```

Windows 若 `python` 不可用，可把上述命令中的 `python` 改为 `py`。依赖版本固定为本次验证使用的 cryptography 46.0.0。程序只监听本机随机端口，不需要外网链节点、管理员权限或钱包余额。

单独运行一组：

```bash
python run_experiments.py --group 2 --output results_group2
```

完整运行应产生 26 行 PASS，并返回退出码 0。出现 FAIL 时先查看该用例的 expected、actual 与异常；不能通过修改预期结果来掩盖系统错误。本包附带 verified_results，保存的是提供者实际执行结果；重新运行的结果默认保存到 results，不会覆盖附带结果。

## 2. 实验模型与固定条件

| 部件 | 本包实现 | 对应后续真实系统 |
|---|---|---|
| 维修终端 | 持有临时 Ed25519 私钥，签名操作请求 | 维修人员终端与设备身份密钥 |
| 授权端 | 本机 HTTP 服务，签发固定测试授权 | 根据工单、人员身份、当前策略签发授权 |
| 网关 | SQLite 保存授权、已用次数、日志、同步状态 | 机器人边缘网关 |
| 机器人 | SQLite 操作回执模拟器，按 op_id 去重 | 支持查询执行状态的本地机器人控制接口 |
| 登记端 | HTTP、内存记录表、签名与序号检查 | 真实合约与链下验证服务 |
| 故障控制端 | 测试程序直接控制远端丢连接、撤销、逻辑时间 | 独立实验控制器与网络故障注入工具 |

每个用例重新生成密钥，使用独立数据库和远端服务。授权固定绑定 gw-1、robot-1、wo-1、第 1 版工单、lease-1、维修人员公钥；只允许 diagnose 和 adjust。默认授权 t=0 签发、t=900 秒到期、最多执行 2 次。900 秒是本实验参数，不是行业规定或推荐最长时长。

断网只切断网关到远端服务的 HTTP/TCP 连接。本地模拟机器人仍可访问。故障开关使服务收到连接后直接关闭、不返回 HTTP 响应；它是应用层的连接故障注入，不等同于完整的物理网络分区，也不测丢包率、心跳检测延迟。

授权有效区间为 `[issued_at, expires_at)`。到期时刻拒绝新操作。执行次数在调用机器人前持久化预留，重启不能归零。同一请求重试返回已有结果，不算新操作。测试时钟由独立控制流程推进，属于可重复的逻辑时间；它不证明设备有可信时钟，也不能用于报告毫秒性能。

远端撤销采取“停止新发和续签，旧租约到原截止时间仍可使用”的明确策略。撤销后的有效旧租约操作计入暴露窗口，不能统计为越权成功。若需要恢复联网后立即拒绝旧租约，必须增加在线撤销检查并另设用例；本包没有实现这一额外策略。

## 3. 六组如何操作和判定

### 第一组：正常流程与身份/范围检查（4 个用例）

命令：`python run_experiments.py --group 1`

1. 在线签发并安装授权，维修终端签名 diagnose 请求，网关执行并上传。
2. 换成另一台机器人，再提交一个有效签名请求。
3. 用另一名人员的私钥签名相同范围的请求。
4. 修改已签授权的 quota，不重新签名，尝试安装。

判定：正常请求为 DONE，登记为 ACCEPTED，机器人回执和登记记录各 1 条；错误机器人为 BAD_SCOPE，错误人员为 BAD_SUBJECT，伪造授权为 BAD_GRANT。拒绝操作不能产生机器人回执。

### 第二组：远端断网（4 个用例）

命令：`python run_experiments.py --group 2`

1. 在线取得授权后切断远端连接；t=120 提交允许的操作，再尝试上传。
2. 没有预存授权就断网；分别尝试取授权和操作机器人。
3. 已缓存授权但断网，提交未在授权列表内的 firmware_update。
4. t=0 签发 900 秒授权，t=800 才断网；t=901 请求操作。

判定：步骤 1 本地 DONE、上传 UNAVAILABLE，日志留在本地；步骤 2 为 NO_GRANT，远端取授权 UNAVAILABLE；步骤 3 BAD_OPERATION；步骤 4 EXPIRED。断网发生时间不能变成有效期起点。

### 第三组：期限与次数边界（4 个用例）

命令：`python run_experiments.py --group 3`

用三个互相独立的初始环境，分别在 t=899、900、901 提交新操作。另一个环境在 quota=2 时连续提交 3 个不同 op_id。

判定：899 为 DONE；900 和 901 为 EXPIRED、无机器人回执；三次操作依次为 DONE、DONE、QUOTA_EXHAUSTED，最终只有 2 条机器人回执。必须检查等于截止时间这一边界，不能只测明显超期。

### 第四组：撤销与恢复连接（4 个用例）

命令：`python run_experiments.py --group 4`

1. t=0 发授权，断网后 t=300 在远端撤销，t=400 离线操作。
2. 远端已经撤销，推进到 t=900，提交新操作。
3. 恢复远端连接，申请新的授权。
4. t=400 完成有效离线操作，到 t=1200 才恢复连接并上传日志。

判定：步骤 1 DONE，属于本策略允许的旧租约使用；步骤 2 EXPIRED；步骤 3 REVOKED；步骤 4 上传 ACCEPTED。登记判断的是声明的执行时刻，不能因为上传较晚而直接认定执行超期。这里对执行时间真实性有假设；签名本身不能证明真实发生时刻。

### 第五组：日志篡改、重复与冲突（4 个用例）

命令：`python run_experiments.py --group 5`

1. 完成操作后修改签名日志的执行时间，不重新签名，再上传。
2. 将同一份日志连续上传两次。
3. 先上传正常日志，再用同一网关密钥签出相同序号、不同内容的第二份日志。
4. 本地产生两条日志，只向登记端展示第一条，且登记端没有独立的末尾序号检查点。

判定：篡改为 BAD_SIGNATURE；重复为 ACCEPTED、DUPLICATE，登记数仍为 1；已观察到的双签为 CONFLICT，保留原记录和两份冲突证据；尾部删除场景只能标为 INDETERMINATE。第四个是能力边界的负对照：登记端接受可见前缀并不能证明日志完整，测试代码没有伪造一个“能自动发现尾删”的检测器。

### 第六组：重启、同步故障与执行中断（6 个用例）

命令：`python run_experiments.py --group 6`

1. quota=1，完成一次操作后关闭并重建网关，重复原请求，再提交另一请求。
2. 登记端保存记录后关闭连接，丢掉响应；网关重试上传。
3. 两条待上传记录，先上传一条，再切断连接；网关重启、恢复连接后继续上传。
4. 已保存机器人回执，但网关未写完成日志时注入中断；重启后查询回执并修复日志。
5. 重启后将时间连续性设为不可信，再提交新操作。
6. 预留次数后、调用机器人前注入中断；重启后尝试恢复和上传。

判定：步骤 1 原请求 REPLAY，新请求 QUOTA_EXHAUSTED、只有一次机器人执行；步骤 2 首次 UNAVAILABLE，重试 DUPLICATE、登记数 1；步骤 3 只补第二条、总数 2；步骤 4 查询回执得到 RECOVERED，不重复调用；步骤 5 CLOCK_UNTRUSTED；步骤 6 NEEDS_RECONCILIATION，上传 PENDING、机器人回执 0，不伪造完成。

此处“中断”是代码中的可控故障点；“重启”是关闭并重建网关对象、重新打开 SQLite，并保持测试密钥。它没有完成操作系统强杀、断电、磁盘损坏或密钥重载验证。真实故障实验必须补上这些步骤。

## 4. 结果文件怎么用

| 文件 | 内容 | 用途 |
|---|---|---|
| results.csv | 每个用例的 group、case、expected、actual、pass | Excel 汇总与逐项核查 |
| results.json | 相同结果的结构化版本 | 自动分析 |
| evidence.json | 已签日志、公钥、远端连接事件、回执数、冲突证据 | 核查“拒绝后无执行”和“重试无重复” |
| scope.json | 实验数量、通过数与实现边界 | 防止论文误写实验范围 |

文件不含私钥。签名与临时端口每次变化是正常现象；用例判定应一致。程序出错导致某个用例失败时，证据文件可能缺少该用例，results.json 会保存异常。不要把 reference 软件测试的 pass 当成真实系统测试的通过。

本包已实际执行：6 组，26 个用例，通过 26 个。没有运行真实链、真实机器人或吞吐量测试；没有生成虚构性能数据。

## 5. 接入你的系统后，才完成论文中的系统实验

保持上述输入、时间点和判定表不变，替换两个适配点：

1. 将 Gateway.execute 的机器人回执模拟段替换成机器人本地 API。接口必须明确 op_id 是否支持幂等、能否独立查询执行状态；若不支持，执行后崩溃可能只能人工核实，不能宣称 exactly-once。
2. 将 RemoteService 的登记模拟器替换成真实合约与链下验签服务。记录网络/链 ID、合约地址、源码提交版本、交易哈希、成功回执、确认规则。哪些检查链上执行、哪些链下执行必须写清；不能只提交日志哈希就声称合约验证了全部授权。

授权模拟端目前签发固定测试输入，没有完整身份鉴别、角色策略和续签逻辑；真实系统必须使用其正式授权接口。本包仅用一个授权、一个网关，顺序执行，不测试并发抢占次数、多网关配额、密钥泄漏或本地数据库恶意回滚。

真实六组应补充以下证据：

- 断网：保留独立控制端故障时间、网关连接错误和本地机器人可达证据；只屏蔽远端服务路径。
- 重启：把网关放在独立进程，在确定的预留/执行/写日志故障点强制终止后重启，保留相同存储并按正式方式重新加载密钥。
- 响应丢失：先从独立登记查询接口证实记录存在，再让网关重试；不要在首次写入前就断网。
- 尾删：增加外部已确认末尾序号检查点，再比较有/无检查点的检测能力。
- 时间：验证实际可信时间方案，测试时钟回拨、重启时间丢失和到期误差；逻辑时钟用例不能替代这一验证。

功能用例先逐项通过。之后再做随机断网与不同 5/15/30/60 分钟授权窗口的性能/暴露窗口实验，预先固定随机种子和重复次数，保存全部失败结果。功能正确性、性能和安全假设分别报告。26 个用例不构成完整安全证明，也不能保证论文录用。
