# 第五阶段停止问题：诊断启动器

截图显示主程序在第 12 组后返回了 CMD 提示符，没有 `Completed runs: 180`。现有材料无法判断是异常、外部中断还是等待问题。本工具收集证据，不预先认定具体根因。

## 操作步骤

1. 解压 `stage5_diagnostic_tools.zip`。
2. 将里面的 `run_diagnostic.cjs` 和 `diagnostic_probe.cjs` 两个文件复制到你现有的 `offline_stage5` 文件夹，和 `run_benchmark.cjs` 放在同一层。
3. 不需要安装依赖，不要替换原来的实验代码。在 VS Code 终端只运行下面这一条：

```cmd
node run_diagnostic.cjs --repeats 1 --output stage5_diag_01
```

先用一次重复诊断。它覆盖 18 组，包括原先停止位置之后的场景。日志仍会显示在终端，同时自动保存，无需手动截取或使用输出重定向。

若该名称已经用过，请改为 `--output stage5_diag_02`。工具拒绝覆盖旧日志和旧结果。若当前还有另一份主实验正在运行，请先结束该运行，再启动诊断，避免同时跑两套影响故障定位。

## 结束后上传什么

程序结束后，现有 `offline_stage5` 目录下会生成三个文件：

- `stage5_diag_01.console.log`：完整标准输出与错误输出。
- `stage5_diag_01.probe.jsonl`：当前运行编号、已保存组数、待完成 RPC、子节点退出事件和未捕获异常。
- `stage5_diag_01.diagnostic.json`：进程退出码、信号、实际完成数量、缺失文件和退出原因类别。

将这三个文件上传，我会据此定位并修复问题。请先不要运行 `audit_benchmark.cjs` 或 `test_audit.cjs`。

## 如何理解提示

- `Diagnostic status: COMPLETED`：主程序退出码为 0，显示 `Completed runs: 18`，结果数量和必需文件齐全。它是完整性检查，不是安全审计。
- `Diagnostic status: INCOMPLETE`：退出、异常或记录不完整，日志保留原因。退出码为 0 但只写了 12 组也会判定不完整，不会当作成功。
- 连续 120 秒没有主程序标准输出或错误输出时，启动器会停止自己启动的主实验子进程，并标注 `timeout: true`。这是诊断超时，不证明死锁；必要时可明确改用 `--idle-seconds 300`。
- 每 10 秒记录一次探针状态到 `.probe.jsonl`。这个探针定时器不会让本来应退出的主进程一直存活。

如果一次重复通过而十次仍失败，再用新的目录执行：

```cmd
node run_diagnostic.cjs --repeats 10 --output stage5_diag_10
```

等本次日志核对后再决定是否执行这条，避免无依据地重复长实验。

## 数据使用限制

诊断器加入了追踪与文件写入开销。本轮结果只用于定位问题，不能和此前正式性能数据混合。诊断器没有修改授权期限、配额、签名验证、机器人调用或链上提交规则，没有自动重试失败实验，也不会生成假的 `scope.json`。

工具的四项合成流程检查已通过：完整完成、退出码 0 但结果不完整、抛出异常、无输出超时。这不是原始实验停止原因已被复现或修复的声明。
