# 第四阶段：离线授权策略的配对对照实验

本阶段回答：离线授权有效期如何影响任务完成率、撤销后的授权暴露和授权请求数量？在同一网络与任务轨迹下，比较严格在线、固定期限和历史自适应三类策略。此处是可复现的合成轨迹策略仿真，结论限于明示模型；真实网关、签名验证、区块链回执与端到端时延需另行测量。

## 1. 在 VS Code 中运行

解压 `offline_maintenance_stage4_comparison.zip`，用 VS Code 打开其中的 `offline_stage4` 文件夹。使用之前的 Python 3.9.13 即可，也支持更新版本。本包只用 Python 标准库，无需 pip、Node.js 或 Ganache。

在该文件夹终端依次执行：

```powershell
python test_rules.py
python run_comparison.py --seeds 30 --output stage4_results
python audit_comparison.py --input stage4_results
```

第一步应显示 9 个测试通过；第二步输出 `Policy runs: 7200`；第三步应显示 `audit_success: true`、重放 7200 次运行、核对 240 组详细记录和 210 组配对区间。

程序拒绝写入已有非空结果目录，避免混合不同实验。重跑请改成 `--output stage4_results_rerun`，并对应修改审计的 `--input`。快速试运行可用 `--seeds 2 --bootstrap 100 --output stage4_smoke`，但它不能替代正式默认矩阵。

运行后压缩你自己生成的 `stage4_results` 文件夹并上传。Windows 可在资源管理器中右键该文件夹，选择“压缩为 ZIP 文件”；或在 VS Code 的 PowerShell 终端执行：

```powershell
Compress-Archive -Path .\stage4_results -DestinationPath .\stage4_results.zip
```

包内 `verified_stage4_complete` 是已核验的参考结果，保留作对照。请上传你本机新生成的结果。

## 2. 实验矩阵与公平性

| 维度 | 设置 |
| --- | --- |
| 网络模式 | 短断网、长短混合、长断网、短转长、长转短，共 5 种 |
| 随机重复 | 每种网络 30 个种子，默认 1000–1029 |
| 风险上限 | low：3600 秒；moderate：900 秒 |
| 场景 | 不撤销、断网期间撤销、联网期间撤销 |
| 策略 | 在线；固定 5/15/30/60 分钟；历史分位数 q50/q90/q95 自适应 |
| 单条轨迹 | 4 小时；离散步长 10 秒 |
| 任务 | 平均到达间隔 90 秒；到达后 120 秒内尝试执行；失败后每 30 秒重试 |
| 配额 | 每张授权最多执行 100 次，所有离线方案相同 |

矩阵为 5 × 30 × 2 × 3 × 8 = 7200 次策略运行，基于 150 条配对轨迹。不能将其表述成 7200 次独立真实系统实验。每条轨迹在所有策略、风险类别间共享断网、任务到达与撤销时刻。

短断网长度为 30–180 秒；长断网为 900–2400 秒；混合场景 70% 为 60–300 秒、30% 为 600–1800 秒。短转长和长转短在四小时轨迹中点改变断网长度分布。在线间隔采用均值 900 秒的指数分布并截在 60–3600 秒范围。任务到达间隔取指数分布，再向上取整到 10 秒。模型初始化提供 40 条历史断网记录，不测量无历史信息的冷启动。

撤销时刻从指定联网/断网状态中的合适时刻随机选取，最迟在实验结束前 3600 秒，以避免最长授权窗口被观测末端截断。这是分层场景比较，并不代表真实撤销发生率。

风险名称和 15/60 分钟上限是实验参数，没有经过行业安全标准验证。固定期限统一受同一风险上限约束，因此 moderate 下固定 15、30、60 分钟实际都是 15 分钟，不能作为三个不同有效期限解释。

## 3. 自适应规则：只使用已结束的断网历史

在每次签发时，取最近 20 条已完整观测的断网长度，计算最近秩经验分位数 Qα：

`TTL = min(风险上限, max(60秒, 向上取整到10秒[2 × (Qα + 30秒)]))`

联网时初次签发，后续在当前授权剩余期限小于等于其初始 TTL 的一半时更新。系数 2 与半寿命续签约定配套，是可检验的启发式设置；分位数水平不是任务完成率保证。尚未结束的断网、实验末端截断的断网均不加入历史。算法不能访问当前断网的未来结束时间。

例如 Q90 = 150 秒时，候选 TTL 为 360 秒；最终还要服从该风险类别的上限。默认主比较在结果产生前固定为 `adaptive_q90` 对 `fixed_15m`，q50/q95 和其他固定期限属于敏感性对照。不要根据结果事后挑出表现最好的一种作为原定主方案。

授权期限从签发时刻计算，断网不会重新计时。撤销后，授权服务拒绝新签发与续签；已有授权在原始到期时间和剩余配额范围内继续有效。联网收到撤销消息也不会自动让已有离线授权提前失效。这一语义必须与论文和实际系统一致。

合法客户端使用最新缓存授权，但新签短授权不会消除之前签发的长授权。实验另报告所有已签授权的保守暴露上界，避免把“新 TTL 变短”误认为“所有旧授权即时失效”。

## 4. 如何解释结果文件

| 文件 | 用途 |
| --- | --- |
| config.json / scope.json | 参数、运行环境、实验范围与假设 |
| traces.json | 完整合成断网、任务、历史和撤销轨迹 |
| run_metrics.csv / .json | 每次策略运行的原始指标 |
| summary.csv / .json | 240 个分组的跨轨迹均值及各指标有效样本数 |
| paired_differences.csv / .json | 210 个分组相对固定 15 分钟的配对均值差和区间 |
| witnesses.json | 每个网络模式第一个种子的完整签发与执行记录，共 240 组 |
| audit.json | 重放、记录审计和区间复算结果 |

关键指标：

- `completion_rate`：无撤销场景用全部任务作分母；撤销场景只用撤销前到达的任务作分母，但允许其在截止期内完成。如果撤销前没有任务，记为 null；汇总与配对比较显式报告有效样本数，不用 0 代替。
- `post_revocation_executions`：撤销后仍被旧授权允许的执行次数，包含撤销后新到达的请求。这是撤销滞后的授权暴露，不是伪造、重放或非法操作的攻击成功次数。
- `capability_exposure_s`：本模型中当前缓存授权在撤销后仍有有效期和配额的累计时间。
- `issued_lease_upper_exposure_s`：撤销到所有已签授权最晚到期的保守窗口，忽略配额和客户端授权替换，因此不代表该窗口中始终能执行。论文同时保留这两种口径。
- `authorization_calls`：逻辑授权请求数，包括模型中的拒绝请求；不是实测 HTTP 请求延迟或 CPU 成本。
- `mean_deferred_upload_wait_s`：接受执行的记录等待下一次联网的平均时间，联网记录等待时间为 0，均纳入分母。
- `max_backlog_records`：离线期间积压记录数峰值；不是磁盘大小或恢复吞吐量。

汇总以每条轨迹的指标为单位取均值，不将不同轨迹任务简单混池。配对 bootstrap 对相同种子的完整轨迹差值重采样，默认 500 次，给出逐项探索性的 95% 百分位区间；未进行多重比较校正，不能直接据此宣称所有比较具有统计显著性。需要更精细区间时可提前固定 `--bootstrap 2000`，保持种子、主比较和全部场景一致。

## 5. 已核验参考结果及其含义

以下仅为本包默认参数的合成轨迹结果，来自 low 风险、不撤销场景，完成率为 30 条轨迹均值：

| 断网模式 | 在线 | 固定 15 分钟 | 自适应 q90 |
| --- | ---: | ---: | ---: |
| 短断网 | 98.30% | 100.00% | 100.00% |
| 长短混合 | 71.33% | 88.36% | 98.98% |
| 长断网 | 41.36% | 69.63% | 99.50% |
| 短转长 | 72.73% | 85.84% | 79.16% |
| 长转短 | 69.16% | 83.96% | 99.98% |

这不能支持“自适应方案全面优于固定期限”。长断网下更长 TTL 提升可用性，也扩大撤销暴露。例如 low 风险、断网撤销场景，长断网模式的所有已签授权保守暴露上界均值，从固定 15 分钟的约 301 秒增加到 q90 的约 2491 秒。短断网下该上界从约 660 秒降到约 232 秒，但不撤销场景的授权请求数均值从约 32 次升到约 73 次。

短转长场景暴露了历史窗口对分布变化的响应滞后；长转短时也可能继续保留较长授权。这些失败与代价应保留在论文中。下一阶段可研究有明确风险预算和变化检测的控制规则，但需要冻结新规则、使用新的测试种子进行检验，避免针对本批结果调参后宣称泛化效果。

## 6. 核验范围与论文使用边界

`test_rules.py` 的 9 个针对性测试覆盖期限边界、断网不重启期限、撤销后的旧授权语义、离线配额、未来信息隔离、共享风险上限、严格在线策略、缩短新授权后保留旧授权上界，以及零任务分母。

审计会用同一模拟器重放全部运行；详细记录检查则另行推导签发历史、期限、配额、执行条件、完成率、授权暴露和队列指标。两者结合有助于发现实现与报告不一致，但不构成形式化安全证明。

本阶段假设网关即时知道联网状态、授权服务零响应延迟、受保护命令瞬时执行；任务不是整个物理维修过程。它不测量心跳故障检测、时间回滚、签名计算、真实机器人动作、EVM gas、区块共识或吞吐量。联网后队列被立即清空，并在轨迹末端施加最终重连，因此上传等待只能作为该模型中的等待指标。前三阶段的功能、故障和真实本地 EVM 回执证据应分别引用，不用本阶段替代。

本阶段为期限策略权衡提供可复现证据。是否达到投稿要求，还需要相关文献定位、可信时钟与威胁假设、明确贡献，以及真实端到端对照，不能保证期刊录用或 Scopus 收录。
